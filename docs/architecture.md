# 設計と制限

```text
frontend/web/src/        Vue・Pinia・Firebase認証・メモリ内キー・WebSocket
backend/cmd/api/         起動・依存注入
backend/internal/httpapi OAuth・Cookie・認証・HTTP・WebSocketの状態制御
backend/internal/agent/  コンテキスト管理・チェックポイント・OpenAI接続
backend/internal/github GitHub本人／権限確認・固定した読み取り専用MCP操作
backend/internal/store/ Firestore保存・lease・期限・削除
backend/internal/domain 対象URL検証・履歴・状態・取得上限
```

## 認証

GitHub AppのOAuthをstate・PKCEで行い、GitHub `/user` で確認したIDからFirebase UIDを生成する。Firebaseカスタムトークンは同一OriginのHTTP応答でだけ返し、URLに入れない。ブラウザーはFirebase ID tokenをAPIへ送り、APIで失効も確認する。

GitHub user access tokenはAES-256-GCMで暗号化したHttpOnly / SameSite=Lax Cookieに保持する。本番はSecure。復号鍵はSecret Managerから供給する。CookieのAADでOAuth state用とGitHub用の用途を分離する。GitHubの有効期限または8時間の早い方で再ログインする。refresh tokenは保持せず、更新は再ログインで行う。Firebaseの本人認証とCookieのUIDを照合する。

WebSocketはOriginと最初の認証フレームを検証し、ユーザーごとの接続leaseを取得する。1ユーザーにつき1接続。45秒のleaseを10秒ごとに更新し、保存時にも同一leaseと期限をトランザクションで検証する。インスタンスが突然終了した場合、最大45秒後に新しい接続が最後の保存状態を取得できる。アプリは切断時にAIを再開せず、ユーザーの操作を待つ。

## AIキー

OpenAIキーはモジュール内のメモリにのみ保持する。Pinia・localStorage・sessionStorage・URLに保存しない。キー入力から最大1時間で破棄し、送信直前にも期限を確認する。セッション切替・終了・ログアウト・ページ終了でも破棄する。サーバーは各実行に必要な間だけキーを参照し、完了・キャンセル時に参照を外す。1実行は最大3分、接続は最大55分。切断・ブラウザー終了後の継続実行は保証しない。

チャットへ一般的なキー形式を入力した場合は拒否する。モデルにキーを本文として渡さず、モデルが当該実行の認証情報を出力した場合も保存を拒否する。メモリの参照破棄はアプリによるコピーの利用停止を意味し、ランタイム／OS上のバイトの即時ゼロ化やOpenAI側でのキー失効を保証しない。OpenAIリクエストは `store:false`。

## 読み取り・コンテキスト

モデルは許可された構造化読み取り要求だけを返す。対象owner/repo、コミット、MCP操作名はサーバーが決定する。GitHub権限を毎回確認し、MCPの `/readonly` と `X-MCP-Readonly:true` を併用する。任意URL、書き込み、コード実行の経路を提供しない。ファイルはセッション作成時に固定したデフォルトブランチのコミットから取得する。PR／Issueの本文・一覧は取得時点の情報であり、レビュー結果やPRヘッド固定を提供する第二段階とは区別する。

| 制限 | 初期値 |
| --- | --- |
| ユーザー本文 | 4,096バイト |
| セッション内の追加指示合計 | 4,096バイト |
| 1質問あたりのGitHub取得 | 最大6回、ファイル要求は最大5件 |
| MCP 1応答 | 最大100 KiB。上限超過は未確認理由として表示 |
| 1取得結果のAI投入 | 最大8,000バイト。後半省略を明示 |
| AI用コンテキストJSON | 最大24 KiB。直近最大6メッセージ・要点2 KiB・指示・直近2取得結果 |
| OpenAIリクエストJSON全体 | 最大40 KiB（システム指示・出力schema込み） |
| AI出力 | 最大4,096トークン／呼び出し、回答16 KiB、要点2 KiB |
| 1質問あたりのAI呼び出し | 最大7回 |
| 会話保存 | 最大200メッセージ、本文合計300 KiB |
| 同時WebSocket接続 | 1インスタンス4接続、1ユーザー1接続 |
| 外部HTTP / 1実行 | 60秒 / 3分 |

入力トークンそのものの事前カウントではなく、まずUTF-8バイト数と呼び出し回数で小さく制限する。実トークン数はOpenAI usageから集計する。上記の出力上限との組み合わせで利用量を制限するが、料金通貨の上限を保証するものではない。料金換算は未実装。

取得結果は実行内のメモリにのみ保持し、同一要求は再取得しない。保存するのは会話、要点、対象コミット、参照リンク、未確認理由、利用量。古い会話本文は必要なら履歴画面で読める。コードの詳細は固定コミットから再取得できる。モデルによる要約は事実の証明ではなく、欠けた詳細は再取得して確認する。

ヒープ値は処理の区切りで観測したGoプロセス全体のHeapAllocの最大値。OS RSS、瞬間ピーク、セッション単体のメモリ使用量を示すものではない。実PRでの負荷試験と上限調整は今後必要。

## 保存と削除

`users/{uid}/sessions/{id}` に状態・会話・要点・参照元・利用量・固定対象・ExpiresAtを保存し、`users/{uid}/locks/connection` に接続leaseを保存する。UIDは検証したトークンからのみ採用する。ブラウザーからのFirestore直接読み書きは全拒否する。

セッションは作成から30日後にアクセス不可。FirestoreのExpiresAtフィールドにTTLを設定するとバックグラウンドで物理削除される。TTLは即時ではない。本人はサイドバーから即時削除できる。接続中は削除を拒否し、UIが切断・lease解放後に再試行する。Firebase認証ユーザーの一括アカウント削除・運営用管理画面は未実装。

コミットに固定されたファイル・ディレクトリ取得は、リポジトリ・コミットSHA・パスをキーにFirestoreの `githubReadCache` へ1時間保存する。毎回GitHubで権限を確認し、失敗した取得は保存しない。期限切れは利用せず、Firestore TTLで後から削除する。PR・Issueは対象外。キャッシュが利用できない場合はGitHubから取得する。

新しいセッションの最初の実行時に固定コミットのREADMEを取得し、目的・主要なファイルやディレクトリの役割・技術構成だけをAIで要約してセッションに保存する。READMEの入力は最大8,000バイト、保存する概要は最大1,400バイト。概要は後続のチャットに背景として渡し、作成元のコミットと省略の有無も添える。取得・要約に失敗しても実行は続ける。既存セッションには自動作成しない。

READMEの概要も同じリポジトリ・コミットであればセッション間で1時間再利用する。利用前にGitHubのリポジトリ権限を確認し、コミットが変わった場合やキャッシュの期限切れ・利用不能時は改めて生成する。概要生成に失敗した結果は保存しない。
