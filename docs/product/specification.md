# AIファクトリー MVP仕様書

AI FactoryはGitHubリポジトリの調査、PRレビュー、変更の実装とDraft PR作成を行うWebアプリである。この文書は現在の実装の動作をまとめる。構成と制約は[設計と制限](../architecture.md)、設定とAPIは[開発ガイド](../development.md)を参照する。

## セッション

GitHub Appでログインし、Appと本人がアクセスできるリポジトリを選ぶ。`owner/repository` またはGitHub.comのリポジトリ・PR・Issue URLからセッションを作成できる。作成時にリポジトリのコミットと、サーバーの許可リストから選んだAIモデルを保存する。

AI接続はOpenAI、Gemini Developer API、Anthropic API、Vertex AI経由のClaudeを使い、モデルに対応するAPIキーまたはアクセストークンを画面で入力する。実行用キーは入力から最大1時間で期限切れとなる。保存を選んだ場合は別のコピーをブラウザーのIndexedDBに残し、次のセッションでも選択できる。保存済みキーは画面から削除する。

会話・進捗・結果はWebSocketで更新する。利用者は実行中に追加指示と停止を送れる。追加指示は受付済みと反映済みを区別し、AI呼び出しの間で反映する。切断すると実行を中断し、再接続時に保存状態を復元する。AI処理の続行には利用者の再開操作を必要とする。CI待機中は接続後に確認だけを自動継続する。

セッションは利用者ごとに分離し、作成から30日でアクセス不可となる。サイドバーから削除できる。同じ利用者による複数接続での二重実行はleaseで防ぐ。

## GitHubチャット

質問に応じてリポジトリ、ファイル、PR、Issue、コメントを段階的に取得し、参照元と未確認の範囲を付けて回答する。AIには直近の会話と要点を渡し、履歴全体やリポジトリ全体を毎回送らない。

画面は取得回数・取得量、入出力トークン、所要時間、観測したプロセスのヒープ値を表示する。登録単価のあるモデルはUSDの推定料金も表示する。AIには依頼の目的と残りの取得予算を渡し、上限に達したら確認できた範囲で回答する。段階別の利用量も表示し、停止中にセッション累計のトークン上限を設定できる。上限到達時は次のAI呼び出し前に止まり、再開時も累計を引き継ぐ。

回答やレビューに挙げたソースファイルはコードパネルで表示し、コピー・個別保存・一括保存できる。参照コミットを表示し、取得できなかったファイルはエラーと再試行の操作を示す。

## PRレビュー

1. チャットでPRを取得し、「このPRをレビューして」と依頼する。PR番号の明示指定も受け付ける。対象が分からない場合は番号を尋ねる。
2. PRのbase/headを固定し、関連するファイルごとにレビュー計画を作る。大きい差分は分割して処理し、処理位置を保存する。
3. 必要な関連コードやコメントを読み、指摘と根拠、未確認の範囲をまとめる。各区切りの要点を全体照合にも使い、複数ファイルの指摘は元コードを確認して採用する。
4. 画面に重要度、ファイル・行、問題、影響、根拠、修正案を表示する。未確認事項は優先度と理由を示し、個別に追加調査できる。

「バックエンドのみ」「フロントエンドのみ」の指定を保持し、対象外の差分をAI入力から除く。共通設定や文書は確認対象に残す。

停止・切断・実行上限の後は保存位置から再開する。PRの更新を検出すると停止し、チャットで再レビューを依頼するよう案内する。以前の結果には対象SHAを残す。

## 実装・Draft PR作成

### 計画と承認

チャットで変更を依頼するか、「実装を依頼」を選ぶ。AIは関連コードを調べ、変更ファイル、方針、依存関係、対象外、リスク、テスト、受け入れ条件を含む計画を提示する。不明点がある場合は質問する。

利用者が「計画を承認して変更を作成」を押した後に編集する。編集中に計画外のファイルが必要になった場合は、理由を示して追加の承認を待つ。見送ったファイルは変更しない。

### 変更と確認

テキストファイルの追加・更新・削除を扱う。更新は元コードに一致する検索・置換、または原文を照合した行範囲の変更として適用する。生成済みの内容を後続の編集に使い、公開前の追加依頼でも既存の変更を保持する。

編集後にAIが変更全体と関連コードを読み、受け入れ条件と整合性を確認する。根拠と修正候補のある指摘は、承認済みの範囲で最大2回自動修正する。未解決の指摘・静的な未確認・条件の未達が残る場合は公開を止め、追加修正や再調査を案内する。

静的検証とビルド・テストの実行結果は区別する。公開後のCIへ委ねる実行確認は `deferredChecks` として表示する。変更後のファイル本文の保存期限は24時間で、期限内なら実装パネルから現在時刻を基準に24時間延長できる。延長はセッションの有効期限を上限とする。期限切れの場合は停止して再度の実装依頼を案内する。

### 公開と追加修正

利用者が差分、ブランチ名、PRタイトル、本文を確認し、「Draft PRを作成」を押すとサーバーがGitHubへ書き込む。新規PRは `ai-factory/` ブランチから作成する。書き込みはAIを呼ばず、AIキーも必要としない。

既存PRの修正はオープンで同じリポジトリにあり、`ai-factory/` で始まるブランチを対象とする。承認・差分確認後に同じブランチへ追加コミットする。他者によるブランチ更新を検出した場合は停止する。

公開後は対象コミットのCIを最大5分確認し、未完了なら接続中は確認だけを自動継続する。成功・失敗・待機・未確認を分け、チェック0件や別コミットの成功を完了根拠にしない。再確認はAIキーなしで行える。失敗時は全失敗ジョブのログを取得して新しい修正計画を作り、利用者の承認後に編集する。

### 変更の制約

計画で承認したパスと操作を検証する。`.git`、`.github/workflows/`、`.github/actions/`、`.gitmodules`、`CODEOWNERS`、パストラバーサル、シンボリックリンク、サブモジュールへの変更を拒否する。バイナリや一部の生成ファイルも拡張子で除外する。判定は [ValidateChangePath](../../backend/internal/domain/change.go) を参照する。

変更内容やPR本文に認証情報らしい文字列があれば拒否する。強制プッシュ、デフォルトブランチへの直接書き込みは行わない。書き込み途中に停止した場合は完了した操作を保存し、再試行時に残りを続行する。

## 固定デモ

GitHubとAIの固定デモを用意しており、外部サービスの資格情報なしで操作を確認できる。認証と保存にはFirebase Emulatorを使う。回答、レビュー、変更はサンプルであり、実リポジトリの内容や生成品質を確認した結果ではない。
