# エージェントの改善内容

エージェントフローの改善案のうち、新しい実行基盤を必要としない4項目を実装した。公開前の対象コード実行と、実モデルによる継続評価は引き続き対象外。

## 探索と編集の予算配分

編集の1区切りの上限は5呼び出しのまま、変更生成と訂正のために3回分を確保する。追加取得だけで3回を消費してから編集に移る経路は、追加取得2回と編集最大3回に変わる。全体の100回・30分の上限、計画承認、公開前の静的検証は維持する。

入力が大きい場合は、取得結果や関連ファイルを一括削除せず、古い取得結果や優先度の低い関連コードから1件ずつ減らす。既に生成したコードを優先して残す。原文の一致条件や保護パスの制限は緩めない。

## ドラフトの保存期限

新しく保存した生成内容は24時間保持する。実装パネルの「保存期限を今から24時間延長」で、セッションの有効期限を上限に延長できる。読み取り専用のリポジトリキャッシュは従来の1時間のまま。

延長は全ファイルが有効な場合に限り、期限のメタデータだけを一度のトランザクションで更新する。期限切れの復活や、新しい編集内容を古い内容で上書きする処理は行わない。導入前に作られた内容は、元の期限内で延長する必要がある。

## 利用量と予算停止

セッション情報に段階別の呼び出し数、入力・出力トークン、時間、対応モデルの概算料金を表示する。実装の再試行も分けて記録する。既存の履歴には過去の段階別情報を補完しない。

同じ画面でセッション累計トークン上限を設定できる。0は上限なし。報告されたusageの累計が上限に達したら次のAI呼び出し前に停止し、再開しても累計をリセットしない。上限は利用者が実行停止中に変更できる。最後の1応答分は超える場合があるため、金額や実トークンの厳密な上限を保証するものではない。
