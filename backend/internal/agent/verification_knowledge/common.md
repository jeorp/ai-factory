# 共通の確認方法

依頼・追加指示・既存の公開契約を優先する。以下は適用条件付きの確認観点であり、新しい要件ではない。該当しない観点から指摘を作らない。

- ERROR-PATH: 失敗時の状態保持が要求される関数では、各error return・throw・例外までに実行される書き込みを列挙する。検証前の初期化、別名経由の変更、defer/finally、外部呼び出しも含め、対象となる全状態を確認する。一つの変数だけ直して同種の問題を残さない。
- EVIDENCE: 指摘にはルールID、実際に読んだパス、該当する関数・分岐・操作、要求に反する具体的な経路を示す。関連する定義や呼び出し元が不足していれば追加取得し、不足が残ればunverifiedにする。コードで問題が確認できた場合だけissuesにする。
- LIMITS: 静的確認は実行結果ではない。テスト成功やデータ競合の不存在を保証したと書かず、実行確認は既存のGitHub CIに委ねる。承認範囲や禁止パスを広げない。
